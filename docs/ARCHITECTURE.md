# 架構

依 HALA 驗證網站需求分析，系統分成三個使用區域。技術上仍是同一個模組化單體。金流沒有服務商金鑰時不會扣款；線上簽約會真的產生含簽名與人像的 PDF。

## 使用者層

| 角色 | 可以做的事 |
|---|---|
| 公開訪客 | 瀏覽前台，不需帳號 |
| 業者／會員 | 註冊後申請、補件、報名課程、簽署合約、查看已登錄的證書 |
| 後台人員 | 承辦審查與出席；管理員另可派案、核定、管理帳號與稽核 |

前台只讓業者自行註冊。內部帳號由管理員建立。

## 系統功能層

公開前台：首頁、關於我們、最新消息、驗證介紹、教育訓練、常見問題、聯絡我們、註冊／登入。

業者會員區：驗證申請、補件、教育訓練、合約簽署、電子證書、續約、已付款、授權資源、業者資料。

內部後台：首頁內容管理（含圖庫輪播）、案件審查、現場複審檢查表、會員、合約範本與發出、方案與付款、教育訓練、報表、角色功能與串接設定、操作紀錄。

首頁 Hero、Banner、合約範本、角色功能與串接開關存在資料庫，由後台修改。其餘說明頁文案仍在 `apps/web/src/content/site-content.ts`。

## 資料層

| 項目 | 現況 |
|---|---|
| 資料庫 | PostgreSQL。展示模式改用瀏覽器資料，不連資料庫。 |
| 第三方金流 | 綠界全方位金流。非正式環境可用文件上的測試商店。付款通知檢查碼正確且不是模擬付款才入帳。 |
| Email | 主控台或 SMTP。可在串接設定停用。主控台不會標成已寄出。 |
| 媒體儲存 | 申請附件、首頁圖片、人像、簽名與合約 PDF 存在本機或 Zeabur Volume。 |
| 線上簽署 | 瀏覽器拍攝人像並收集手寫簽名，API 產生 PDF。 |

## 程式分層

```text
apps/web  → 只呼叫 Services
              ├─ mock（VITE_DATA_MODE=mock，正式建置會拒絕）
              └─ http（VITE_DATA_MODE=api，失敗不改走 mock）
apps/api  → Express /api/v1
packages/contracts → 狀態、驗證、權限、API schema、示範資料
packages/db → Prisma schema 與只給伺服器使用的 client
```

瀏覽器不可 import `@mf/db/server`。

個別帳號可勾選功能。線上簽約可產生含人像與簽名的 PDF。自訂報表可同時組合案件、業者、訓練報名、合約的欄位，在畫面上以表格、長條圖或圓餅圖查看，也可以下載 CSV。金流仍不扣款。
