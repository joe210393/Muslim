# 待確認事項

這些項目沒有正式資料。程式使用標成示範的內容，不把示範名稱當成正式類別。

| 項目 | 目前假設 | 正式上線影響 |
|---|---|---|
| 七類正式名稱與審查表 | `CAT_01` 顯示「第 1 類：廚房／餐廳相關（名稱待確認）」；其餘為「第 N 類（待提供正式名稱）」。`configurationStatus` 為 `DEMO` | 未確認前，正式環境 `DEMO_MODE=false` 會拒絕用這些類別送件 |
| 第 1 類第 2 版 | 多一個 `serviceHoursNote`，只供示範舊案不自動改版 | 正式欄位待業主提供後另建 form version |
| 統一編號 | 暫定 8 位數字；海外或無統編規則未定 | 不能直接當正式驗證規則 |
| 完課門檻 | 線下仍以出席分鐘計算。線上課程改為看完上傳影片時間的三分之二才算通過。教育時數不擋案件核定 | 若業主要求先上課才能送件，需另開工單 |
| 課程回饋 | 教育訓練列表有這個欄，目前不能填 | 正式回饋表未提供，欄位先標尚未開放 |
| 證書 | 管理員在核定後人工登錄編號與日期 | 沒有自動發證。合約 PDF 是另一份簽署檔 |
| 聯絡窗口 | `contact@example.test` | 需換成正式窗口後才能公開 |
| 郵件、簡訊、LINE | 主控台郵件標為 `MOCKED`，不標 `SENT` | 正式 SMTP 尚未申請 |
| 備份 | 文件說明手動 `pg_dump` 與 Volume | 沒有排程，不能當成已備份 |
| 前台文案、FAQ、消息 | 首頁 Hero／Banner 由內容管理寫入資料庫。其餘初稿在 `apps/web/src/content/site-content.ts` | 正式稿可在後台覆蓋首頁，其餘仍替換該檔 |
| 費用與金流 | 方案金額可建立。結帳走綠界全方位金流測試商店，付款通知檢查碼正確且不是模擬付款才改成已付款。公開費用表金額仍是「待填」 | 甲方註冊後改 ECPAY 環境變數。正式環境沒有商店金鑰時不能結帳 |
| 朝拜時間表 | 只留欄位，不填推測時間 | 需甲方提供資料來源 |
| 現場複審檢查表 | 依廚房／餐廳類推論五項 | 正式檢查表、拍照與錄影規則替換同一清單 |
| 合約、續約、授權資源 | 示範合約可簽署並下載 PDF。業者可把已簽署合約登記為已續約或未續約。法律效力、費用與是否重新現場複審未定 | 後台可新增範本與版本。已發出的合約不能再改內文。正式法律文字仍待貼上 |
| 個別權限勾選 | 三種角色的功能開關已可儲存並擋下對應 API | 若要改成每人一組權限，需另開工單 |
