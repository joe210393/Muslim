# 待確認事項

這些項目沒有正式資料。程式使用標成示範的內容，不把示範名稱當成正式類別。

| 項目 | 目前假設 | 正式上線影響 |
|---|---|---|
| 七類申請表 | 類別名稱與申請內容／附件依七個資料夾空白申請表各自固定：餐廳（申請項目擇一＋餐點種類五項勾選）、旅宿（含／不含早餐）、環境、體驗活動、商店、旅行社、產品（表頭仍寫食用品）。不可跨類別勾選項目。舊案件維持原本表單版本 | 產品表頭「食用品」與資料夾名「產品」是否正式統一待確認。教育時數仍沒有寫在表上 |
| 餐廳餐點附件分組 | 空白表附件四～六未依餐點種類分列；畫面勾選拆成五項後，早餐／午餐／晚餐對應「早／午／晚餐」菜單與食材附件，飲品／點心對應另一組同名附件。附件一～三仍共用。依證書區分與業者說明實作 | 若官方要求兩組共用同一組上傳欄，或飲品／點心附件名稱不同，需再改 |
| 第 1 類舊版 | 第 1、2 版仍是示範欄位，只留在已建立的舊案件 | 不把舊案件改到新表單 |
| 統一編號 | 空白申請表寫無則免填。有填仍暫定 8 位數字；海外規則未定 | 不能把 8 碼當成正式統編檢查 |
| 完課門檻 | 線下仍以出席分鐘計算。線上課程改為看完上傳影片時間的三分之二才算通過 | 一般課時數仍不擋案件核定 |
| 基礎教育訓練 | 帳號開通後須完成示範基礎課（標題／YouTube／需觀看百分比／教材，可多門）與題庫抽題測驗，才可建立／送出驗證申請。觀看達設定百分比後由系統標示完成，不可自行點完成。測驗通過只在教育訓練顯示「已完成」，不發證書。證書僅線上／線下課程與專班完課後由承辦人工登錄。抽題數、及格題數、是否擋申請、專班最低人數由後台「門檻設定」可改。題庫以後台表單新增／編輯為主，檔案匯入為進階選項 | 正式教材、題庫內容、各課正式觀看百分比待甲方提供後替換 |
| 訓練證書 | 基礎課通過後自動產 PDF。一般線上／線下課由管理員對完課報名人工登錄編號與效期 | 自動證效力、一般課是否也要自動證待確認 |
| 業者專班申請 | 人數達門檻才可送出，管理員核准或退回；初版核准後不自動建課，可選填對應課程 | 費用、場地與開課流程待確認 |
| 課程回饋 | 教育訓練列表有這個欄，目前不能填 | 正式回饋表未提供，欄位先標尚未開放 |
| 證書 | 核定後依類別／項目對應範本；後台可編輯／預覽範本（對齊合約內文排版）。發證寫入編號、效期、範本鍵與 HTML 快照；業者電子證書可預覽與下載 PDF。一案目前一張證書（管理員於對應範本中擇一） | 同案多張證書（如正餐＋飲品）是否要一次發兩張待確認。正式 PDF 是否需像素級還原 docx（浮水印／簽名圖）待確認 |
| 聯絡窗口 | `contact@example.test` | 需換成正式窗口後才能公開 |
| 郵件、簡訊、LINE | 本機 `.env` 若填 Gmail SMTP，展示畫面的發送會寄到對方信箱；主機仍是 `127.0.0.1` 時只進 Mailpit。補件、流程下一步、續約會自動寄。手動信可寄給一位或全部業者。自動本文可在寄信頁修改，已寄出的不回寫 | 正式站的 SMTP 還要另外設在 Zeabur，不要把應用程式密碼提交進 git。續約付款方式未定 |
| 備份 | 文件說明手動 `pg_dump` 與 Volume | 沒有排程，不能當成已備份 |
| 前台文案、FAQ、消息 | 首頁 Hero／Banner 由內容管理寫入資料庫。其餘初稿在 `apps/web/src/content/site-content.ts` | 正式稿可在後台覆蓋首頁，其餘仍替換該檔 |
| 費用與金流 | 流程：業者選方案（未核案件）→ 管理員核准後產生匯款單（未付款）→ 業者上傳繳費單據（未核付款）→ 管理員核帳（已核帳）→ 開通教育訓練與合約 → 基礎教育訓練通過後才能驗證申請。不核准、改為未成立或逾期都成「未成立」，上傳鎖定，要重新申請。方案可指定可見使用者（未指定＝全體）。方案目錄依《2026內部報價》。綠界程式還在，但目前流程不走 | 是否使用金流（規格標待確認）、稅金 5% 是否另列、印尼方案是否上架待確認 |
| 匯款單收款帳戶 | 銀行、帳號、戶名在「設定 → 匯款單」由管理員填；目前空白，匯款單顯示「待管理員設定」並提醒先聯絡窗口 | 需正式收款帳戶。匯款單目前即時讀設定，改帳戶後舊匯款單也會顯示新帳戶；若要保留開單當時的帳戶需另存 |
| 繳費期限 | 核准當天起算 14 天（台北時間當日 23:59:59），可在設定改 1～90 天。退回單據重傳不延長期限 | 14 天是暫定值。退回後是否延長、逾期是否先提醒再作廢待確認 |
| 開發票 | 規格第二階段寫「繳費及開發票」。系統只做到核帳，沒有開發票或上傳發票 | 發票由誰開、是否要在系統上傳或寄送待確認 |
| 付款通知信 | 核准、不核准、退回、逾期都只在業者頁面顯示，沒有寄信 | 是否要寄信、寄信時機與內文待確認 |
| 朝拜時間表 | 只留欄位，不填推測時間 | 需甲方提供資料來源 |
| 現場複審檢查表 | 紙本檢查項目仍依 2026 年兩份檢查表對照。系統改為：業者只上傳送件附件；複審以同一批附件核對通過／沒通過，必要時可選現場拍照存證 | 現場結果在 `site_checks`。現場照片 `captured_on_site` 掛在送件附件項，不取代業者原照。業者申請端不再上傳檢查表照片。錄影規則未見於檢查表 |
| 合約、續約、授權資源 | 核帳後發約；選業者會帶出尚未完成合約的申請類別（多筆可選）。範本為視覺編輯器（HTML／表格／分組勾選／大小章）。立約方獨立成 PDF 末頁。業者下載→蓋章→上傳。管理／業者指揮台：待上傳或未簽訂／已簽約／可續約／未續約。後台可上傳大小章電子檔 | 正式章圖檔是否另有版權／用印規範、續約付款流程、其他類別合約是否分範本待確認 |
| 個別權限勾選 | 三種角色的功能開關已可儲存並擋下對應 API | 若要改成每人一組權限，需另開工單 |
| 1124 案件八階段 | 規格寫八階段：註冊報價、繳費及開發票（專案免付）、設施改善、提交申請書及簽約、現場查核、教育訓練、審核通過、核發證書。新狀態名稱包含未核案件、未付款、未申請、未成立、未核付款、未初審、未核簽約、未複審、未補件、未核補件、未核複審、複審紀錄、未學習、證書核發。付款已改為未核案件、未付款、未核付款、已核帳、未成立（新增 `VOID`）。案件只改顯示名稱：未申請、未初審、初審中、未複審、未核複審、未補件、審核通過、未成立；資料庫 enum 與狀態機沒改。未核簽約、未核補件、複審紀錄、未學習還沒有對應狀態 | 規格自己標了三件待確認：是否使用金流、合約是否改為紙本用印掃描、現場教育訓練是否要簽名與註記。這三件沒有定案前，不再拆案件狀態。規格裡舊流程圖的位置未提供新圖 |
| 前台頁面編輯 | 頁面名稱與「放進頁首」存草稿就生效，但前台只列已發布頁。內容區塊要按發布才換。需 `cms.edit`，管理員與有此功能的承辦都能改所有頁面，沒有送審流程 | 頁面改動是否要第二人覆核再上線、承辦是否可改前台待確認 |
